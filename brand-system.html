07  Motion

The rule: motion resolves, it does not loop. Graphics form once on arrival, settle within about 2.5 seconds, then either rest or drift slowly enough to read as atmosphere. Looping motion competes with reading the headline — that was learned the hard way.

ConcernApproach
FormationCSS transitions triggered by an IntersectionObserver: [data-reveal] gains .in, then the observer stops watching it
Continuous motionSMIL, never CSS transforms on <g>. CSS transforms on SVG groups proved unreliable and silently failed twice
Transform conflictsEvery animateTransform sits alone on a bare group with no competing transform attribute
CentringScale and rotate wrap in a static translate pair, or they pivot on the SVG origin
Reduced motionsite.js removes every SMIL node, since CSS cannot switch it off
The one exception: the FAQ waveform runs continuously. A still waveform reads as broken, so voice is the one place where looping is correct.

09  Architecture

site.css     shared — tokens, reset, nav, buttons, sections, footer, focus, type scale
site.js      shared — reveal observer, reduced-motion SMIL strip, theme toggle
*.html       page-specific CSS in a <style> block, loaded after site.css

CSS went from 350 KB duplicated across eight pages to about 30 KB cached once, plus page-specific blocks.

Cache busting is not optional here. Both shared files carry a content hash — site.css?v=…. While the CSS was inlined, editing a style also changed the HTML, so caches invalidated themselves. Extracting the stylesheet removed that safety net: the HTML can be identical while site.css has changed underneath it. Regenerate the hash with md5sum after any edit.
